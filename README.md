# Prompt-to-PostFX

**自然语言 → 参数配方 → WebGL2 实时后处理管线**

输入「雨夜霓虹的赛博朋克城市，颗粒感重，轻微故障艺术」，
AI **不生成图像**，只输出一组后处理参数；GPU 按这组参数逐帧重绘画面。

可交互、可动画、参数可调、能进实时管线 —— 这是它与"文生图"的根本差别。

---

## 为什么不让 AI 直接画图

| | 文生图 | 本项目 |
|---|---|---|
| AI 的输出 | 像素 | 参数配方（JSON） |
| 结果形态 | 一张静态图 | 实时渲染的画面 |
| 能否调参 | 只能重抽 | 16 个滑杆逐项可调 |
| 能否动画 | 不能 | 每帧可驱动 |
| 能否进游戏管线 | 不能 | 能，且可移植到移动端 |
| 结构准确性 | 会被模型改写 | 由真实画面决定 |

面试时这一句话就是核心论点：**AI 在环，渲染兜底。**

## 跑起来

零依赖、零网络请求、零 API key：

```
双击 index.html          # 直接打开，所有代码与示例图都在文件里
双击 启动.bat            # 重建 index.html 并打开
python server.py        # 本地服务 http://127.0.0.1:8931/
python _verify.py       # 一键全量验证：构建 → 逻辑断言 → 真机渲染断言 → 出截图
node _smoke.js          # 只跑逻辑层冒烟测试（84 项）
```

`_verify.py` 会自己找 Chrome 与 node，找不到时用 `CHROME=/path/to/chrome`、
`NODE=/path/to/node` 指定。只依赖 Python 3 与 node 16+，不需要 `pip install`。

改完 `src/` 里的源码后必须重跑 `build.py`（或 `启动.bat`）——`index.html` 是内联产物。

## 管线设计

执行器只认三种 pass 类型，**新增一个效果 = 往注册表加一条**，不用改执行器：

- `full`：读当前链 → 写 ping-pong 里的另一张 → 交换（读写的 RT 永不同一，无反馈环）
- `aux`：读指定源 → 写辅助 RT，不进主链（辉光用半分辨率跑在这里）
- `final`：读当前链（+辅助图）→ 写到屏幕

| # | pass | 类型 | 说明 |
|---|---|---|---|
| 00 | 输入归一化 | — | cover 到画布尺寸，成为整条链的稳定输入 |
| 01 | 色彩分级 | full | 曝光 / lift / gamma / gain / 色温 / 对比 / 饱和 / 染色 |
| 02 | 辉光 · 亮部提取 | aux ½ | 亮度阈值提取 |
| 03 | 辉光 · 横向模糊 | aux ½ | 9 tap 可分离高斯 |
| 04 | 辉光 · 纵向模糊 | aux ½ | 9 tap 可分离高斯 |
| 05 | 描边 | full | Sobel 边缘检测 |
| 06 | 色差 / 故障 | full | 径向色散 + 行错位 |
| 07 | 网点 | full | 可调角度半调屏 |
| 08 | 合成输出 | final | 辉光叠加 · 扫描线 · 颗粒 · 暗角 |

每个 pass 都可单独关闭，执行器直接跳过 —— 这条链是可插拔的。
每个 pass 独立编译，**单个着色器编译失败只禁用自身，不拖垮整条管线**。

## 解析层

**锚点 patch 是绝对目标值，修饰词 patch 是增量** —— 这个区分必须守住：

```js
// 锚点：赛博朋克"就是"这组数，多锚点时按占比插值，未分配的残差留在基础值上
{ grade: { gain: [0.90, 0.94, 1.30], gamma: [1.06, 1.00, 0.94], sat: 1.30 } }

// 修饰词：在结果之上"再加一点"
{ grain: { intensity: 0.11 } }
```

14 个风格锚点（赛博朋克 / 水墨 / 胶片 / 漫画网点 / 蒸汽波 / 恐怖 / 清新日系 /
故障艺术 / 黄昏 / 冷冽 / 黑白极简 / 梦核 / 油画 / 电影感）
+ 16 个修饰词（颗粒 / 暗角 / 色差 / 扫描线 / 辉光 / 描边 / 网点 …）
+ 程度词（非常 / 很 / 极其 → ×1.45；轻微 / 略微 → ×0.55）。

匹配采用**长词优先 + 区间互斥**，避免「赛博朋克」同时命中「赛博」重复计权。

| 真机渲染 | 无头 Chrome + SwiftShader —— GL 管线建得起来、8 个着色器全部编译通过、**中性配方渲染结果 == 原图**、7 组提示词出图彼此可区分 |

真机渲染的四个关键字段：


**为什么要分两层**：逻辑断言查不出几何/视觉缺陷。下面三个坑里有两个是逻辑断言全绿、
只有截图能发现的。

## 实现中踩到的三个真坑

**1. 屏幕空间效果的尺寸要按像素算，不能按 UV 算。**
颗粒原本写 `floor(vUV * scale * 900.0)`，画布一变大格子就小于一个像素，
`floor()` 跳格采样，噪点退化成规则的网格摩尔纹。改成 `floor(vUV * uRes / scale)`
让格子等于固定的像素尺寸。网点同理。

**2. 参数语义必须全表统一。**
最初一半锚点写的是增量、一半写的是绝对值，结果伽马被叠成 1.7：
画面过曝、暗部出现块状色带，而**所有断言都还是绿的**（因为它们只检查相对方向）。
现在锚点一律绝对、修饰词一律增量，并加了一条回归断言：
*单独应用任何锚点都必须天然落在区间内，钳制不该在正常路径上生效。*

**3. 示例图里的水面倒影是刀切直边。**
倒影原本用「一条**纵向** linearGradient + 一个 fillRect」画出来：纵向有衰减，
但左右两条边是垂直于水面的直线。原图看着还行，可一旦经过调色把对比拉开
（赛博朋克那类强增益），就变成一块刺眼的矩形亮斑 —— **看起来像后处理链出了 bug**。
一个 gradient 表达不了两个方向，改成沿 y 切 64 条窄带、每条内部用横向软边渐变，
带宽随深度递增、alpha 随深度衰减。修复后该区域最大单列跳变从 **+15.2 降到 +5.5**。

## 定位方法（比结论更值得抄）

第三个坑一开始被误判成管线问题。定位它的流程是可复用的：

**第一步：先判断是源图自带还是管线产生。**
把除调色之外的所有 pass 全关（`iso_onlyGrade`），异常还在 → 不在后处理链里。
这一步就排除了 8 个 pass 里的 7 个。

**第二步：单变量隔离，而不是读代码猜。**
`_iso.js` 读 URL hash 决定关掉哪一项，`_iso.py` 对 10 个变体各截一张图，
`_iso_analyze.py` 用数值指标（竖向边缘能量、列均值剖面的硬台阶数）给它们排序。
比"盯着代码想"快一个数量级。

```bash
python _iso.py && python _iso_analyze.py
```

**第三步：改完补断言，并且证明断言有牙齿。**
新增 `_smoke.js` 的 **B7 组**用「记录式 canvas 桩」把画出来的形状断言下来
（倒影必须是多条横向渐变窄带、宽度单调、相邻重叠）。然后做变异测试：

```bash
python _mutate.py                                    # 生成把倒影改回旧写法的变异体
SMOKE_SAMPLE=_mutant_sample.js node _smoke.js         # 必须看到 5 条 FAIL
node _smoke.js                                       # 原版必须 84/0
```

> **空集恒真陷阱**：B7 第一次写出来时，「没有硬边倒影」这条是**恒真的** ——
> 录制桩把 `fill` 记成了 `undefined`，过滤结果为空，`every()` 对空数组返回 true，
> 断言以「0 条硬边」通过。所以必须补一条 *"确实录到了窄条"* 的正向断言，
> 否则桩坏掉时测试会安静地失效。

**第四步：`uTime` 驱动的效果在测试里必须显式传时间。**
故障类效果按 `floor(uTime * 9.0)` 抖动，若用 `performance.now()`，同一配方的两次抓取
结果不可复现，隔离实验会得出随机结论。为此加了 `__PPFX__.grab(recipe, w, h, t)`
这个固定时间渲染原语。
